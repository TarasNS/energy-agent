How the harness works

Read this once before the hackathon. It takes five minutes.

In one sentence

The AI decides which tool to use next. Code decides what the AI is allowed to do, and what the number is.

One review, step by step

What happens after someone clicks Run review

  1. The screen sends the request

    Portfolio, zone, month, threshold. From the Lovable screen, or the local fallback page.

  2. The harness starts the agent loop

    It sends the model three things: the curtailment-advisor skill, the request, and the list of five tools.

    Files: harness/README.md

  3. The model asks for a tool

    For example list_assets. The harness runs the real Python function, writes an audit line, and sends the result back.

  4. This repeats

    The model asks for the next tool: production, prices, then the calculator. At most 10 rounds (STEP_BUDGET).

  5. The calculator makes the number

    calculate_curtailment_value returns the EUR by cause. The harness keeps that output. A review that never calls it fails.

  6. The model explains

    It writes the explanation and the recommendation, and may call propose_action. Then it stops.

  7. The harness builds the result

    The numbers are copied from the calculator output, never from the model's text. The result also lists the tools used, in order.

  8. A person approves

    On the screen: name, then Approve. This is outside the loop; the model has no approval tool.

  9. Everything is in the audit log

    Each tool call, the proposal and the approval are one line in artifacts/audit.jsonl.

What the model can and cannot do

Enforced in code, not in the prompt

Can

  • Choose which of the five tools to call, and in what order
  • Read portfolio, production and price data
  • Ask the calculator for the EUR result
  • Explain the result and recommend a step
  • Propose an action

Cannot

  • Make up or change a number: the screen shows calculator output only
  • Skip the calculator: the review fails
  • Approve or execute an action: there is no tool for it
  • Write data, run shell commands or browse the web
  • Run forever: it stops after 10 rounds

What fails, on purpose

Each one has a test

  • The model calls a tool that is not registered: error result, nothing runs.
  • The model never calls the calculator: the review fails with a clear message.
  • 10 rounds pass without an answer: the review stops with a clear message.
  • Approve with a missing, wrong or reused token: refused, nothing executed, audit line written.
  • No internet: MODEL_PROFILE=offline replays recorded model turns through the same loop.

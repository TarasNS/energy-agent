Set up

Once, before you build

  1. Open the project in Claude Code

    In the Claude desktop app, choose the Code tab and open the folder energy-agent. No folder yet? Ask Claude to clone it in the next step. The repository holds documents and checks only: that is expected.

  2. Let Claude set it up

    Claude installs the tools and runs the checks. You read the answer.

    Tell Claude

    Set up this project on my computer. If the code is not here, clone https://github.com/TarasNS/energy-agent.git. Switch to the main branch, run make setup and make check, and explain any failure in plain words. If make is not installed (common on Windows), run python scripts/dev.py setup and python scripts/dev.py check instead, and from now on read every make X in this project as python scripts/dev.py X. Do not ask me to type my API key in this chat.

    You should see: make check passed.

  3. Choose Haiku 5.5

    In Claude Code, pick Claude Haiku 5.5 in the model menu. It is fast; the tasks are cut small so it can do each one well. If a test stays red after two fixes, stop and ask.

  4. Add the key

    Ask the lead for the Anthropic key. Copy .env.example to .env, paste the key after ANTHROPIC_API_KEY= and save. Never commit it.

    Files: .env.example

  5. Read the idea and the contract (10 minutes)

    These two files. Claude reads the rest for you. There is no harness code to copy: the team builds it together from the contract.

    Files: INTENT.md, SPEC.md

  2. #9 · Server routes

    Task #9 of 24 · round 1 · needs: nothing, start now · branch dev4/server-routes · see the flow

    Nothing else is needed. The page and the smoke test only need these routes, not the real loop.

    Files: SPEC.md

    1. Brief Claudethen reply go

      Paste into Claude Code

      Read INTENT.md, SPEC.md and CLAUDE.md first. Then do this task:
Build tools/kpi-lab/server.py with the Python standard library, as in SPEC.md section 8. make_server(agent, approve) returns a server with these routes: POST /api/chat {question} returns agent(question), a dict shaped as in SPEC.md section 8; POST /api/approve {proposal_id, approver} returns approve(proposal_id, approver), a dict {status}; GET /health returns {status: "ok", calls_left_today}. Count model calls per day against KPI_DAILY_CAP (default 200), stored in KPI_CAP_FILE; when the cap is used up, /api/chat answers 429. Allow cross-origin calls only from the origins in KPI_ALLOWED_ORIGINS (comma separated): answer the browser's OPTIONS preflight and include Access-Control-Allow-Private-Network: true, so the Lovable page on the internet can call a server on this computer. Host and port come from KPI_LAB_HOST and KPI_LAB_PORT (default 127.0.0.1 and 8000). In this task the agent is a fake that returns one fixed verified answer and approve is a fake that returns {"status": "approved"}. Tests first in tools/kpi-lab/test_server.py: each route, a 429 after the cap, a refused origin, an allowed preflight, an unknown route answering 404.

How we work, start to finish

  1. The lead settles the idea

    Read INTENT.md (five minutes). The lead answers its three open questions.

    Files: Lead page

  2. Everyone sets up once

    Open your page from the tiles above and paste the setup prompt. Claude installs the tools and runs the checks.

  3. Each person takes their tasks

    Four developers, two or three tasks each. The order is on your page.

  4. Build each task with Claude

    One prompt to start, one to finish. Test first, then the verifier, then a pull request. See the loop.

  5. The parts meet on GitHub

    One pull request per task into main. The lead merges. See how.

  6. The lead prepares the presentation

    Five slides and the three-minute demo.

    Files: Presentation, DEMO.md

  7. Rehearse, merge to main, deploy

    Twice, once with Wi-Fi off. Then the lead deploys main to Azure. See how.

How we put our parts together

Nobody sends files by chat or e-mail, and there is no shared folder. GitHub is the one place where our parts meet. Every part arrives as a pull request.

  1. Work on your own branch

    The brief prompt on your page makes branch devN/<task> from main. You never edit main directly.

  2. Finish with the finish prompt

    Claude runs make check and make test, pushes your branch and opens a pull request into main. There is no automatic build: the local checks are the gate.

  3. The lead merges

    The lead merges each pull request into main. One pull request per task. Then tell the lead in the team chat.

  4. Update before the next task

    Paste this at the start of every task.

    Tell Claude

    Update main from GitHub, create my next branch dev<N>/<task> from it, and tell me in plain words if anything conflicts.
  5. Two people changed the same file?

    Stop. The ownership table in TEAM.md decides who owns it. Do not resolve it yourself.

    Files: TEAM.md

    Tell Claude

    Show me which files conflict and who owns each one. Explain the conflict in plain words. Do not change anything.

Deploying to Azure

The chat runs as one container on Azure App Service. Azure builds the image, so nobody needs Docker on a laptop. The container files exist on branch feature/docker-deploy and are not on main yet: that is Dev 3's third task.

PartHow it works
Imagepython:3.11-slim with only the runtime code. .dockerignore is an allowlist, so .env, tests and docs never enter the image.
Build and runaz acr build builds in Azure. The web app pulls the image with its managed identity.
The keyANTHROPIC_API_KEY is an App Service setting. It is never in the image or in git.
SettingsKPI_DAILY_CAP (default 100 model calls a day), KPI_ALLOWED_ORIGINS (sites allowed to call the API), KPI_LAB_HOST, KPI_LAB_PORT, KPI_CAP_FILE, AUDIT_LOG_PATH.
CheckGET /health returns 200 and the calls left today.
Known limitIt runs as root because App Service mounts /home writable for root only. Fine for the POC.

Not confirmed yet: the Azure names (registry, web app, resource group) and who has access. They are not in the repo. The lead confirms them before the first release.

  1. Pull main first

    Only deploy main, after make verify is green.

  2. Release

    The lead pastes this into Claude Code. Claude asks for the names and for approval before it changes anything in Azure.

    Tell Claude

    Build the container image from main in Azure Container Registry, update the web app to the new image, then call /health and tell me the result. Ask me for the registry, web app and resource group names, and ask before every az command that changes Azure. Never print the API key.
  3. Check the live page

    Open the page, ask one question, and confirm an answer and a chart come back. Then press Approve on a proposal and check the audit line.

How every task flows

One small task, one branch, one pull request. You never type a command: each step is a prompt you paste into Claude Code.

Brief Claude with one prompt and check the plan. Claude builds, tests and fixes until green. A second prompt runs the verifier and the checks, then opens the pull request. The lead merges.

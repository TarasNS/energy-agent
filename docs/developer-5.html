Set up

Once, before you build

  1. Open the project in Claude Code

    In the Claude desktop app, choose the Code tab and open the folder energy-agent. No folder yet? Ask Claude to clone it in the next step. The repository holds documents and checks only: that is expected.

  2. Let Claude set it up

    Claude installs the tools and runs the checks. You read the answer.

    Tell Claude

    Set up this project on my computer. If the code is not here, clone https://github.com/TarasNS/energy-agent.git. Switch to the main branch, run make setup and make check, and explain any failure in plain words. If make is not installed (common on Windows), run python scripts/dev.py setup and python scripts/dev.py check instead, and from now on read every make X in this project as python scripts/dev.py X. Do not ask me to type my API key in this chat.

    You should see: make check passed.

  3. Choose Haiku 5.5

    In Claude Code, pick Claude Haiku 5.5 in the model menu. It is fast; the tasks are cut small so it can do each one well. If a test stays red after two fixes, stop and ask.

  4. Add the key

    Ask the lead for the Anthropic key. Copy .env.example to .env, paste the key after ANTHROPIC_API_KEY= and save. Never commit it.

  1. #11 · Chat page in Lovable

    Task #11 of 24 · round 1 · needs: nothing, start now · see the flow

    The page needs nothing from this repository; the shapes are in SPEC.md sections 8 and 9.

    Files: SPEC.md

    1. Brief Lovablethen check the preview

      Paste into Lovable

      Build a one-page chat for portfolio managers called "Energy 4.0 Harness · KPI chat". Show a SYNTHETIC DATA label at all times. A question box and an Ask button. The answer area shows a chat result with these fields: text, verified (true or false), note, charts, proposals, trace, stopped. When verified is true, show the text. When verified is false, hide the text and show the note, the charts and the tool results instead. A chart is {id, kind: line, bar, area or table, title, series: [{name, points: [{x, y}]}]}. Every y is a string: show it exactly as given and never add, round or average values. Under the answer, a collapsible "Tools used" list from trace ({tool, input, ok}). Each proposal {id, action, asset, reason, status} is a card with a name field and an Approve button; Approve stays disabled until a name is typed; show the status pending, approved or refused in words. Also show these states: loading, daily limit reached, server not reachable, server error. For now use example data, not a server: one verified answer with a bar chart, one withheld answer, and one answer with a proposal. Phone and desktop layouts. Colours: dark green #1A5C00, near black #1C1C1C, off-white #F4F2EB.
    2. Checkmust work

      You should see: every state shows in the Lovable preview at phone and desktop width, and the page calculates nothing.

    3. FinishLovable commits

      In Lovable, connect the project to GitHub. Lovable keeps the code in its own repository: name it energy-agent-ui under TarasNS. Share the repository link and the page's address with the team.

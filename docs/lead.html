The whole picture

The number on each box is its developer. Point at a name to see their part.

Decide first

Three open questions in INTENT.md, section 10

  1. Pick the first real data source

    Without a validated source no KPI is production-ready. Name one source and one owner, or confirm the POC stays synthetic.

    Files: INTENT.md (§10), KPI_REVIEW.md

  2. Confirm who owns the calculator

    mcp/kpi-solar is assigned to Dev 2 in TEAM.md. Say yes or name someone else.

    Files: TEAM.md

  3. Choose the demo host

    The Azure container, or the presenter's laptop. Offline replay (Dev 1) is the fallback either way. Make sure you have access to the Azure registry and web app.

    Files: Deploying to Azure

Before the build

Four prompts, each takes a minute

  1. Add names to the team file

    Files: TEAM.md

    Tell Claude

    Open TEAM.md and replace Dev 1 to Dev 4 and Lead with these names: <names>. Change nothing else.
  2. Check the spec with an energy colleague

    15 minutes. Are the KPI definitions right, and are the data ranges plausible?

    Files: KPI_REVIEW.md, SPEC.md

  3. Keep the team off the old build

    The earlier build is kept on tag reference-v1 so you can compare at the end. Tell the team not to open it.

    Tell Claude

    Tell me what is on tag reference-v1 and confirm that main has no harness code. Do not change anything.
  4. Share the key privately

    One Anthropic key for the team. Each developer puts it in their own .env; it is never committed.

  5. Send each person their page

    Link: docs/developer-N.html. Each person runs the setup prompt on their page before the session.

The loop

How every task reaches main

During the build

  1. Merge in build order

    Dev 1 contracts first, then Dev 2 portfolio and formulas, then Dev 3 tools and loop, then the rest. The order is in ARCHITECTURE.md section 6.

    Files: ARCHITECTURE.md, SPEC.md

  2. Check main after every merge

    Tell Claude

    Update main from GitHub, run make verify and tell me in plain words what is red and who owns it.
  3. Say no to new scope

    If it is not on someone's page, it is after the POC. See INTENT.md section 8.

    Files: INTENT.md

  4. Never add an approval tool to the registry

    Nine tools. Approval is never one of them.

Prepare the presentation

The lead owns the story

  1. Read the five slides

    Open the page and read them aloud once.

    Files: Presentation

  2. Change the words

    Slide text is in one file. Claude edits it and rebuilds the page.

    Files: scripts/slides.py

    Tell Claude

    Edit the slides in scripts/slides.py. Change: <what to change>. Keep each slide to a headline and at most three short items. Then run make docs and tell me what changed.
  3. Check the demo story

    The three-minute story and the questions to ask live.

    Files: DEMO.md

    Tell Claude

    Open DEMO.md and run each question in the demo table against the chat page. Tell me which questions give a good answer and which do not, and suggest replacements. Do not change any code.

Before presenting

  1. Compare with the earlier build

    Only you may open tag reference-v1. Ask the same five questions on the new build and on it, and judge how close they are. Differences are fine; wrong numbers are not.

    Tell Claude

    Run the new harness and the build on tag reference-v1 side by side in separate folders. Ask both: Which park lost most energy in June? / What is our battery round-trip efficiency? / Should we change anything about negative prices? / What was the total revenue of park A in 2031? / Add up the energy of both parks and give me the average. Show a table: tools used, chart yes or no, verified yes or no, and the first 200 characters of each answer. Do not edit any file.
  2. Run the end-to-end check

    Tell Claude

    Run make demo-smoke and tell me if it passes offline.
  3. Rehearse twice, once with Wi-Fi off

    Time it. It must be under three minutes. Save one screenshot per step as the fallback.

    Files: DEMO.md

  4. Deploy to Azure

    Use the release prompt on the front page.

    Files: Deploying to Azure

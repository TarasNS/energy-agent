Energy 4.0 Harness

One workflow, five developers, one session. Monthly Curtailment Review for a DK1 solar portfolio on synthetic data.

It proves three things: the number can be trusted, the model can be swapped, and no action happens without a person.

Agent loop

Based on the template harness-course-build, trimmed. The model chooses from five tools and stops after 10 rounds.

Five tools

list_assets, get_production, get_day_ahead_prices, calculate_curtailment_value, propose_action. Approval is not a tool.

Screen

Built in Lovable on synthetic data. A local HTML page is the offline backup.

Five rules

  1. Code owns the number. Every EUR value comes from the calculator. A review without a calculator call fails.
  2. Data tools only read.
  3. A person approves. One-time token, checked in code.
  4. Everything is logged. Tool calls, proposals and approvals go to the audit log.
  5. Works offline. Synthetic data and recorded model replies. No real data or keys in Lovable.

Step by step

Before the event

  1. Lead confirms names and approves the plan.
  2. Lead writes the Lovable challenge brief: problem, context, who it affects, data.
  3. Dev 5 accepts the Lovable invite and uploads only synthetic data.
  4. Everyone clones the repo and runs make setup.
  5. Dev 3 renames workflow/ to harness/.
  6. Schemas frozen.
  7. Dev 4 works out the golden cases by hand.
GATE Nobody builds until these seven steps are done.

Build

  1. Start in parallel: T1.1, T2.1, T2.3, T3.1, T3.2, T4.1, T5.1.
  2. Then: T1.2 skill, T2.2 agent loop, T4.2 calculator.
  3. Then: T3.3 offline replay, T2.4 offloader, T4.3 eval, T5.2 tool trace.

Connect

  1. make demo-smoke passes offline.
  2. Lovable screen calls the review API.
  3. make check and make test pass; merge.

Present

  1. One timed run.
  2. One run with Wi-Fi off.
  3. Present: the number, the tool trace, a refused approval, the audit line.
